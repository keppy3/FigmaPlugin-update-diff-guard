# Update Diff Guard

Figmaでコンポーネントを更新（またはライブラリの最新版に更新）した際に、意図しない見た目の変化（オーバーライドのリセットなど）が起きていないかを、Before/After比較で確認できるFigmaプラグインです。詳細な仕様は[Spec.md](Spec.md)を参照してください。

現在はSpec.md通りのタブ構成・ストリーミングスキャン・個別/一括操作・Latestを重ねて配置（重ね表示トグル）を実装済みです。

## Figmaへの読み込み方（ビルド不要）

`dist/code.js` と `dist/ui.html`（Figmaが実際に読み込むファイル）は**ビルド済みのものをリポジトリに含めています**。Node.js/npmが入っていないマシンでも、`git clone`（または`git pull`）するだけでそのまま動きます。

1. Figmaデスクトップアプリを開く。
2. メニュー → Plugins → Development → **Import plugin from manifest…**
3. このフォルダ内の `manifest.json` を選択。
4. メニュー → Plugins → Development → **Update Diff Guard (dev)** を選んで実行。

## ソースを編集する場合（Node.js/npmが使える環境のみ）

```bash
npm install
npm run build
```

`npm run watch` を使うと、保存のたびに自動でビルドされます。ソースを変更したら再ビルドし、**`dist/code.js` と `dist/ui.html` の変更もあわせてコミット・pushしてください**（ビルドしない環境で `git pull` するだけで最新化できるようにするため）。再ビルド後はプラグインを再実行するだけでよく、Figma側での再インポートは不要です。

## 動作確認でチェックすること

1. ライブラリ側に新しいパブリッシュ版があるコンポーネントのインスタンスを複数含むフレーム（一部は見た目差分あり・一部はなし・できればサイズが変わるものも1つ含める）を選択し、**スキャン範囲**を選んで **スキャン** を実行する。
2. スキャン中、結果が1件ずつ「見た目差分なし」「見た目差分あり」タブに流れ込むこと、上部の「確認中… n / 全体数」の進捗が更新されることを確認する。**キャンセル**を押すと、途中経過を保持せずスキャン前画面に戻ることを確認する。ヘッダーの**リセットボタン**を押しても同様に最初の画面に戻ることを確認する（一括 更新・一括 Latestを重ねて配置中はグレーアウトして押せないことも）。ヘッダーには「Update Diff Guard」という静的な文言はなく、動的なステータス（「アイドル」「スキャン中…」「検出完了」等）だけが表示されることも確認する。
3. 「✅️ 見た目差分なし」タブ:
   - 行を展開し、サムネイル1枚（更新後の見た目）とその下の「Current = Latest」ラベル（ニュートラルな色。緑ではない）が正しく表示されるか確認する。サムネイル右脇に緑文字の「完全一致」バッジ（背景なし）と **ジャンプ** ボタンが縦に並んでいることを確認する。
   - 個別の **更新する** を押すと、その行だけリストから消えることを確認する。
   - **すべて選択｜すべて解除**、**すべて展開｜すべて折りたたむ**（4つとも同じ青いリンク色）が期待通り動くか確認する（後者2つはボタンを押した瞬間に全行を強制的に開閉するだけで、ラベル自体は変化しない）。チェックボックスをShiftキーを押しながらクリックし、直前にクリックした行との間が範囲選択されるか確認する。
   - 手動で数行だけ展開した状態で、他の行の更新など別の操作を行っても、展開状態が維持される（勝手に閉じない）ことを確認する。
   - 複数チェックして **一括 更新**（青Fill）を押すと、ビジー画面が表示され、完了後にチェックした行だけリストから消えることを確認する。
   - 行リストの最下部に「対象外・更新なし (N)」というアコーディオンが**デフォルト折りたたみ**の状態で表示され、展開すると対象外のインスタンス（名前＋理由）が並ぶか確認する。**チェックボックスが付いていないこと**、対象リストと同じスクロール領域内（別枠のスクロールではない）に収まっていることを確認する。
4. 「⚠️ 見た目差分あり」タブ:
   - 行を展開し、Current・Latestのサムネイルが**常に2枚横並び**で表示されること（差分画像の表示は行わない）、それぞれの下に「Current」「Latest」ラベルが付くことを確認する。サムネイル右脇に、サイズが一致していれば黄文字の「差分◯◯%」、一致していなければ赤文字の「サイズ不一致」（いずれも背景なし）と **ジャンプ** ボタンが縦に並んでいることを確認する。差分率が実際に加えたオーバーライドから予想される内容と一致するか確認する。
   - 各行に **このまま更新**（青アウトライン）と、配置前は **Latestを重ねて配置**（オレンジアウトライン）の1つだけが表示されることを確認する。
   - 個別の **Latestを重ねて配置** を押した**瞬間**（処理が完了する前）にキャンバスがCurrentの位置へジャンプすることを確認する。その後、Currentとまったく同じ座標・同じサイズの位置（レイヤー上もCurrentの直上）に、Latestインスタンスを内包したラッパーFrameが配置されることを確認する。ラッパーFrameに **strokeWeight 20px・Outside・#FF00FF（マゼンタ）** のアウトラインが付いており、Latestインスタンス自体には直接ストローク等が追加されていないことを確認する。
   - 配置後、「Latestを重ねて配置」ボタンが**「Latestを削除」（赤アウトライン）＋目玉ボタン「表示/非表示」**の2つに置き換わることを確認する。目玉ボタンを押すたびにラッパーFrame（＝Latestインスタンス）の表示/非表示が切り替わり、Currentと完全に重なった状態で見た目を見比べられることを確認する。ボタンのテキストは変わらず、アイコン（開いた目/閉じた目）だけが状態に応じて変わることを確認する。
   - 個別の **Latestを削除** を押すと、その行のラッパーFrameだけが削除され、ボタンが「Latestを重ねて配置」に戻ることを確認する（他の行の配置済みプレビューには影響しないこと）。
   - 個別の **このまま更新** を押すと確認ダイアログが出て、本文に加えて「（Latestを重ねて配置している場合、それを削除します）」という注釈（マゼンタ文字）が表示されることを確認する。続行した**瞬間**（実際の書き込みが行われる前）にキャンバスが対象インスタンスへジャンプし、その後その1件が更新されリストから消えることを確認する（Latestを重ねて配置済みだった場合、対応するラッパーFrameも自動的に削除されることを確認する）。
   - タブ最下部のボタンが上から**「一括 このまま更新」（青Fill）／「一括 Latestを重ねて配置」（オレンジアウトライン）＋「一括 Latestを削除」（赤アウトライン、横並び）**の順で並んでいることを確認する（個別行のボタン順「このまま更新→Latestを重ねて配置」と揃っている）。
   - 複数チェックして **一括 Latestを重ねて配置** を押すと配置され、その後 **一括 Latestを削除**（チェック済み・配置済みの行のみ対象。それ以外はグレーアウト）を押すとまとめて削除され、各行が「Latestを重ねて配置」ボタンに戻ることを確認する。
   - 複数チェックして **一括 このまま更新** を押すと確認ダイアログ（同じ注釈付き）を経由して一括更新されることを確認する（一括実行時はキャンバスの自動ジャンプは行われない）。
   - 「配置中の最新インスタンス（プレビュー）: N件」の表示が正しい件数になっているか、**すべて削除**（チェック状態を問わず全件が対象）を押すとラッパーFrame・Latestインスタンスがすべて消えるか確認する。あわせて、削除された行のボタンが「Latestを重ねて配置」に戻ることも確認する。
5. いずれの操作でも、対象インスタンスにFigJamの矢印が接続されている場合、操作後も矢印が繋がったままかを確認する（これがこのプロジェクト全体の存在理由となる制約。Spec.md §1参照）。
6. Ctrl+Zで、直前の操作（更新／Latestを重ねて配置／表示切替／プレビュー削除）だけが取り消され、それより前の操作には影響しないことを確認する（`figma.commitUndo()` によるUndo境界。Spec.md §10）。
7. スキャン中に、対象インスタンスの1つを削除するか別の場所に移動してみる。そのインスタンスが「対象外（比較中にエラーが発生しました）」として除外されるだけで、スキャン全体が止まらずに続行することを確認する（Spec.md §10「スキャン中にファイルを編集した場合」）。
