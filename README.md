# Update Diff Guard

Figmaでコンポーネントを更新（またはライブラリの最新版に更新）した際に、意図しない見た目の変化（オーバーライドのリセットなど）が起きていないかを、Before/After比較で確認できるFigmaプラグインです。詳細な仕様は[Spec.md](Spec.md)を参照してください。

以前は「検証ビルド」としてフラットな一覧UIのみでしたが、現在はSpec.md通りのタブ構成・ストリーミングスキャン・個別/一括操作を実装済みです（下記チェックリストは実装移行前の検証ビルドでの確認項目を引き継いだものです）。

## Figmaへの読み込み方（ビルド不要）

`dist/code.js` と `dist/ui.html`（Figmaが実際に読み込むファイル）は**ビルド済みのものをリポジトリに含めています**。Node.js/npmが入っていないマシンでも、`git clone`（または`git pull`）するだけでそのまま動きます。

1. Figmaデスクトップアプリを開く。
2. メニュー → Plugins → Development → **Import plugin from manifest…**
3. このフォルダ内の `manifest.json` を選択。
4. メニュー → Plugins → Development → **Update Diff Guard (dev)** を選んで実行。

## ソースを編集する場合（Node.js/npmが使える環境のみ）

```bash
npm install
npm run build
```

`npm run watch` を使うと、保存のたびに自動でビルドされます。ソースを変更したら再ビルドし、**`dist/code.js` と `dist/ui.html` の変更もあわせてコミット・pushしてください**（ビルドしない環境で `git pull` するだけで最新化できるようにするため）。再ビルド後はプラグインを再実行するだけでよく、Figma側での再インポートは不要です。

## 動作確認でチェックすること

1. ライブラリ側に新しいパブリッシュ版があるコンポーネントのインスタンスを複数含むフレーム（一部は見た目差分あり・一部はなし・できればサイズが変わるものも1つ含める）を選択し、**スキャン範囲**を選んで **スキャン** を実行する。
2. スキャン中、結果が1件ずつ「見た目差分なし」「見た目差分あり」タブに流れ込むこと、上部の「確認中… n / 全体数」の進捗が更新されることを確認する。**キャンセル**を押すと、途中経過を保持せずスキャン前画面に戻ることを確認する。ヘッダーの**リセットボタン**を押しても同様に最初の画面に戻ることを確認する（一括更新・一括マーキング中はグレーアウトして押せないことも）。
3. スキャン完了後、除外内訳（「対象外◯件・更新なし◯件」）を展開し、想定通りのインスタンスがそこに入っているか確認する。
4. 「見た目差分なし」タブ:
   - 行を展開し、更新後の見た目（After画像）が正しく表示されるか確認する。
   - 個別の **更新する** を押すと、その行だけリストから消えることを確認する。
   - **すべて選択／すべて解除**、**すべて展開／折りたたむ** が期待通り動くか確認する。チェックボックスをShiftキーを押しながらクリックし、直前にクリックした行との間が範囲選択されるか確認する。
   - 複数チェックして **一括更新** を押すと、ビジー画面が表示され、完了後にチェックした行だけリストから消えることを確認する。
5. 「見た目差分あり」タブ:
   - 行を展開し、差分画像（pixelmatchの出力）と差分率が、実際に加えたオーバーライドから予想される内容と一致するか確認する。
   - サイズが変わるインスタンスの行では、差分画像の代わりにCurrent（更新前）・Latest（更新後）の2枚が並んで表示されることを確認する。
   - 個別の **マーキングする** を押すと、その行が**リストに残ったまま**チェックボックスが無効化され「マーキング済み」バッジが付くことを確認する。
   - キャンバス上で、元インスタンスに**赤い**矩形マーカー＋「Current」ラベル、Afterインスタンスに**緑の**矩形マーカー＋「Latest」ラベルが、それぞれ正しく配置されているか確認する（Afterインスタンス自体にはストローク等が追加されていないこと）。
   - 個別の **構わず更新** を押すと確認ダイアログが出て、続行するとその1件が更新されリストから消えることを確認する。
   - 複数チェックして **一括マーキング** / **一括で構わず更新**（一括マーキングの下にある、輪郭のみの控えめなボタン）を押すと、それぞれ同様の結果が一括で起きることを確認する（一括で構わず更新も確認ダイアログを経由する）。
   - 「このページのマーカー: N件」の表示が正しい件数になっているか、**すべて削除**を押すとマーカー・Afterインスタンス・ラベルがすべて消えるか確認する。
6. いずれの操作でも、対象インスタンスにFigJamの矢印が接続されている場合、操作後も矢印が繋がったままかを確認する（これがこのプロジェクト全体の存在理由となる制約。Spec.md §1参照）。
7. Ctrl+Zで、直前の操作（更新／マーキング／マーカー削除）だけが取り消され、それより前の操作には影響しないことを確認する（`figma.commitUndo()` によるUndo境界。Spec.md §10）。
8. スキャン中に、対象インスタンスの1つを削除するか別の場所に移動してみる。そのインスタンスが「対象外（比較中にエラーが発生しました）」として除外されるだけで、スキャン全体が止まらずに続行することを確認する（Spec.md §10「スキャン中にファイルを編集した場合」）。
