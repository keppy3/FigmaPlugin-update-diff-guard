# Update Diff Guard

Figmaでコンポーネントを更新（またはライブラリの最新版に更新）した際に、意図しない見た目の変化（オーバーライドのリセットなど）が起きていないかを、Before/After比較で確認できるFigmaプラグインです。詳細な仕様は[Spec.md](Spec.md)を参照してください。

現在はSpec.md通りのタブ構成・ストリーミングスキャン・個別/一括操作・最新インスタンス配置（重ね表示トグル）を実装済みです。

## Figmaへの読み込み方（ビルド不要）

`dist/code.js` と `dist/ui.html`（Figmaが実際に読み込むファイル）は**ビルド済みのものをリポジトリに含めています**。Node.js/npmが入っていないマシンでも、`git clone`（または`git pull`）するだけでそのまま動きます。

1. Figmaデスクトップアプリを開く。
2. メニュー → Plugins → Development → **Import plugin from manifest…**
3. このフォルダ内の `manifest.json` を選択。
4. メニュー → Plugins → Development → **Update Diff Guard (dev)** を選んで実行。

## ソースを編集する場合（Node.js/npmが使える環境のみ）

```bash
npm install
npm run build
```

`npm run watch` を使うと、保存のたびに自動でビルドされます。ソースを変更したら再ビルドし、**`dist/code.js` と `dist/ui.html` の変更もあわせてコミット・pushしてください**（ビルドしない環境で `git pull` するだけで最新化できるようにするため）。再ビルド後はプラグインを再実行するだけでよく、Figma側での再インポートは不要です。

## 動作確認でチェックすること

1. ライブラリ側に新しいパブリッシュ版があるコンポーネントのインスタンスを複数含むフレーム（一部は見た目差分あり・一部はなし・できればサイズが変わるものも1つ含める）を選択し、**スキャン範囲**を選んで **スキャン** を実行する。
2. スキャン中、結果が1件ずつ「見た目差分なし」「見た目差分あり」タブに流れ込むこと、上部の「確認中… n / 全体数」の進捗が更新されることを確認する。**キャンセル**を押すと、途中経過を保持せずスキャン前画面に戻ることを確認する。ヘッダーの**リセットボタン**を押しても同様に最初の画面に戻ることを確認する（一括処理：更新・一括処理：最新インスタンス配置中はグレーアウトして押せないことも）。ヘッダーには「Update Diff Guard」という静的な文言はなく、動的なステータス（「アイドル」「スキャン中…」「検出完了」等）だけが表示されることも確認する。
3. 「見た目差分なし」タブ:
   - 行を展開し、更新後の見た目（After画像）が正しく表示されるか確認する。
   - 個別の **更新する** を押すと、その行だけリストから消えることを確認する。
   - **すべて選択／すべて解除**、**すべて展開／折りたたむ** が期待通り動くか確認する。チェックボックスをShiftキーを押しながらクリックし、直前にクリックした行との間が範囲選択されるか確認する。
   - 複数チェックして **一括処理：更新** を押すと、ビジー画面が表示され、完了後にチェックした行だけリストから消えることを確認する。
   - タブ最下部（一括処理：更新ボタンの下）に除外内訳（「対象外◯件・更新なし◯件」）が表示され、展開すると想定通りのインスタンスが内訳に入っているか確認する。
4. 「見た目差分あり」タブ:
   - 行を展開し、差分画像（pixelmatchの出力）と差分率が、実際に加えたオーバーライドから予想される内容と一致するか確認する。
   - サイズが変わるインスタンスの行では、差分画像の代わりにCurrent（更新前）・Latest（更新後）の2枚が並んで表示されることを確認する。
   - 各行に **ジャンプ**「このまま更新」「最新インスタンス配置」「最新インスタンスの表示」（目玉ボタン）の4つが常に表示され、配置前は「最新インスタンスの表示」がグレーアウトしていることを確認する。
   - 個別の **最新インスタンス配置** を押すと、Currentインスタンスとまったく同じ座標・同じサイズの位置（レイヤー上もCurrentの直上）に、Latestインスタンスを内包したラッパーFrameが配置されることを確認する。ラッパーFrameに **strokeWeight 20px・Outside・#FF00FF（マゼンタ）** のアウトラインが付いており、Latestインスタンス自体には直接ストローク等が追加されていないことを確認する。また、配置完了と同時にキャンバスがその位置へ自動的にジャンプする（選択・ズームイン）ことを確認する。
   - 配置後、「最新インスタンス配置」ボタンがグレーアウトし、代わりに「最新インスタンスの表示」ボタンが押せるようになることを確認する。押すたびにラッパーFrame（＝Latestインスタンス）の表示/非表示が切り替わり、Currentと完全に重なった状態で見た目を見比べられることを確認する。ボタンのテキストは変わらず、アイコン（開いた目/閉じた目）だけが状態に応じて変わることを確認する。
   - 個別の **このまま更新** を押すと確認ダイアログが出て、続行するとその1件が更新されリストから消えることを確認する（最新インスタンス配置済みだった場合、対応するラッパーFrameも自動的に削除されることを確認する）。
   - 複数チェックして **一括処理：最新インスタンス配置** / **一括処理：このまま更新**（一括処理：最新インスタンス配置の下にある、輪郭のみの控えめなボタン）を押すと、それぞれ同様の結果が一括で起きることを確認する（一括処理：このまま更新も確認ダイアログを経由する。一括実行時はキャンバスの自動ジャンプは行われない）。
   - 「配置中の最新インスタンス（プレビュー）: N件」の表示が正しい件数になっているか、**すべて削除**を押すとラッパーFrame・Latestインスタンスがすべて消えるか確認する。あわせて、削除された行が「最新インスタンス配置」ボタンを再度押せる状態（「最新インスタンスの表示」はグレーアウト）に戻ることも確認する。
5. いずれの操作でも、対象インスタンスにFigJamの矢印が接続されている場合、操作後も矢印が繋がったままかを確認する（これがこのプロジェクト全体の存在理由となる制約。Spec.md §1参照）。
6. Ctrl+Zで、直前の操作（更新／最新インスタンス配置／表示切替／プレビュー削除）だけが取り消され、それより前の操作には影響しないことを確認する（`figma.commitUndo()` によるUndo境界。Spec.md §10）。
7. スキャン中に、対象インスタンスの1つを削除するか別の場所に移動してみる。そのインスタンスが「対象外（比較中にエラーが発生しました）」として除外されるだけで、スキャン全体が止まらずに続行することを確認する（Spec.md §10「スキャン中にファイルを編集した場合」）。
